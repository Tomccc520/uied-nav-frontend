### 为什么需要 API？

**传统方式（硬编码）：**
- 数据写死在代码里
- 修改内容需要改代码、重新部署
- 不适合非技术人员维护

**API 方式（动态数据）：**
- 数据存在数据库里
- 通过管理后台修改，实时生效
- 任何人都可以管理内容

---

## 🌐 API 是什么？

API（Application Programming Interface）= 应用程序接口

简单理解：**API 就是前端和数据库之间的"服务员"**

```
前端想要数据 ──请求──▶ API ──查询──▶ 数据库
前端收到数据 ◀──响应── API ◀──返回── 数据库
```

### 本项目的 API 接口

| 接口地址 | 方法 | 作用 |
|---------|------|------|
| `/api/categories` | GET | 获取所有分类 |
| `/api/websites` | GET | 获取所有网站 |
| `/api/websites?category=xxx` | GET | 获取某分类的网站 |
| `/api/settings/nav-menus` | GET | 获取导航菜单 |
| `/api/settings/footer-groups` | GET | 获取页脚内容 |
| `/api/settings/friend-links` | GET | 获取友情链接 |
| `/api/admin/websites` | POST | 添加网站 |
| `/api/admin/websites/:id` | PUT | 修改网站 |
| `/api/admin/websites/:id` | DELETE | 删除网站 |

### 测试 API

在浏览器直接访问：
- http://localhost:3001/api/health - 检查服务是否运行
- http://localhost:3001/api/categories - 查看所有分类
- http://localhost:3001/api/websites - 查看所有网站

## 🗄️ 数据库结构

使用 **Prisma ORM** + **SQLite** 数据库

### 数据表说明

| 表名 | 作用 | 字段 |
|------|------|------|
| Category | 分类 | id, name, slug, icon, color, order |
| Website | 网站 | id, name, description, url, categoryId, isNew, isFeatured, isHot, tags |
| NavMenu | 导航菜单 | id, text, link, external, label, parentId, order, visible |
| FooterGroup | 页脚分组 | id, title, order, visible |
| FooterLink | 页脚链接 | id, text, url, groupId, order, visible |
| FriendLink | 友情链接 | id, name, url, order, visible |

### 查看数据库

会打开 http://localhost:5555 可视化查看和编辑数据

## 🚀 开发流程

### 1. 启动所有服务

```bash
# 终端1 - 启动后端
cd backend
npm run dev

# 终端2 - 启动管理后台
cd admin
npm run dev

# 终端3 - 启动前端
cd frontend
npm start
```

### 2. 开发顺序

1. **后端先行** - 定义数据结构，创建 API
2. **管理后台** - 实现数据管理界面
3. **前端对接** - 将硬编码数据改为 API 调用

### 3. 前端对接步骤

以导航菜单为例：

**之前（硬编码）：**
```tsx
// 数据写死在组件里
const menuItems = [
  { text: '首页', link: '/' },
  { text: '快讯', link: '/news' },
];
```

**之后（API调用）：**
```tsx
// 从 API 获取数据
const [menuItems, setMenuItems] = useState([]);

useEffect(() => {
  fetch('http://localhost:3001/api/settings/nav-menus')
    .then(res => res.json())
    .then(data => setMenuItems(data));
}, []);
```

## ❓ 常见问题

### Q: 为什么要分三个项目？
A: 职责分离，便于维护和部署。前端可以部署到 CDN，后端可以独立扩展。

### Q: SQLite 够用吗？
A: 对于小型项目完全够用。如果数据量大，可以换成 MySQL 或 PostgreSQL。

### Q: 如何部署？
A: 
- 前端：`npm run build` 后部署到 Nginx 或 Vercel
- 后端：部署到服务器，使用 PM2 管理进程
- 管理后台：同前端
