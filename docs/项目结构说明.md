## ✅ 推荐部署方案：单域名

### 为什么推荐单域名？

| 优势 | 说明 |
|------|------|
| ✅ 简单 | 只需一个域名，无需配置子域名 |
| ✅ 省钱 | 不需要额外购买域名 |
| ✅ 易维护 | 类似 WordPress 的访问方式 |
| ✅ SEO友好 | 所有内容在同一域名下 |

### 访问结构

```
yourdomain.com/              → 前端（用户访问）
yourdomain.com/admin/        → 管理后台
yourdomain.com/api/          → 后端 API
```

## 📦 构建和部署

### 1. 构建前端

```bash
cd frontend
# 修改 .env
REACT_APP_API_URL=/api
npm run build
# 输出到 build/ 目录
```

### 2. 构建管理后台

```bash
cd admin
# 修改 .env
VITE_API_URL=/api
npm run build
# 输出到 dist/ 目录
```

### 3. 上传文件

```bash
# 前端文件 → 根目录
frontend/build/* → /www/wwwroot/yourdomain.com/

# 管理后台 → admin 目录
admin/dist/* → /www/wwwroot/yourdomain.com/admin/

# 后端代码 → backend 目录
backend/* → /www/wwwroot/yourdomain.com/backend/
```

### 4. Nginx 配置

```nginx
server {
    listen 80;
    server_name yourdomain.com;
    root /www/wwwroot/yourdomain.com;

    # 前端
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 管理后台
    location /admin {
        alias /www/wwwroot/yourdomain.com/admin;
        try_files $uri $uri/ /admin/index.html;
    }

    # 后端 API
    location /api {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $host;
    }
}
```

## 🔄 对比其他方案

### 方案对比

| 方案 | 域名数量 | 配置难度 | 推荐度 |
|------|---------|---------|--------|
| **单域名** | 1 | ⭐ 简单 | ⭐⭐⭐⭐⭐ |
| 子域名 | 3 | ⭐⭐ 中等 | ⭐⭐⭐ |
| 多域名 | 3+ | ⭐⭐⭐ 复杂 | ⭐⭐ |

### 单域名方案优势

1. **成本低** - 只需一个域名
2. **配置简单** - 一个 Nginx 配置搞定
3. **维护方便** - 所有服务在一起
4. **用户友好** - 类似 WordPress 的体验

## 📊 资源占用

### 服务器要求

| 配置 | 最低 | 推荐 |
|------|------|------|
| CPU | 1核 | 2核 |
| 内存 | 512MB | 1GB |
| 磁盘 | 5GB | 10GB |
| 带宽 | 1Mbps | 5Mbps |

### 实际占用

- Node.js 进程：~50MB
- 数据库文件：~10MB（10万数据）
- 静态文件：~20MB
- **总计：~80MB**
