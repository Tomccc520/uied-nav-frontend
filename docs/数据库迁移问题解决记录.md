# 数据库迁移问题解决记录

## 问题背景

在 Docker 部署环境中，运行 `npx prisma migrate deploy` 时报错：

```
Error: P3005
The database schema is not empty.
```

## 问题原因

1. 生产数据库已经有表结构和数据
2. Prisma 的 `_prisma_migrations` 表没有记录这些迁移已执行
3. Prisma 尝试重新执行迁移时，发现表已存在，报错

## 解决步骤

### 步骤 1：查看迁移文件列表

```bash
docker exec -it uied-api ls prisma/migrations
```

输出示例：
```
20251223063716_init
20251223065534_add_settings
20251223092930_add_site_info
20251223103540_add_social_media
20251224093434_add_pages
20251224102226_add_category_tree
```

### 步骤 2：标记迁移为已应用（基线化）

对每个迁移文件执行 `migrate resolve --applied`，告诉 Prisma "这个迁移已经应用过了，不需要再执行 SQL"：

```bash
# 一条一条执行，不要一次性粘贴多条！
docker exec -it uied-api npx prisma migrate resolve --applied "20251223063716_init"
docker exec -it uied-api npx prisma migrate resolve --applied "20251223065534_add_settings"
docker exec -it uied-api npx prisma migrate resolve --applied "20251223092930_add_site_info"
docker exec -it uied-api npx prisma migrate resolve --applied "20251223103540_add_social_media"
docker exec -it uied-api npx prisma migrate resolve --applied "20251224093434_add_pages"
docker exec -it uied-api npx prisma migrate resolve --applied "20251224102226_add_category_tree"
```

### 步骤 3：验证迁移状态

```bash
docker exec -it uied-api npx prisma migrate deploy
```

应该显示：`No pending migrations to apply.`

### 步骤 4：如果数据库缺少字段

如果代码中使用了新字段但数据库没有，需要手动添加：

```bash
# 在宿主机执行，通过管道传入 SQL
echo "ALTER TABLE Website ADD COLUMN isPinned INTEGER DEFAULT 0;" | docker exec -i uied-api npx prisma db execute --stdin
echo "ALTER TABLE Website ADD COLUMN isHot INTEGER DEFAULT 0;" | docker exec -i uied-api npx prisma db execute --stdin
echo "ALTER TABLE Website ADD COLUMN isFeatured INTEGER DEFAULT 0;" | docker exec -i uied-api npx prisma db execute --stdin
echo "ALTER TABLE Website ADD COLUMN isNew INTEGER DEFAULT 0;" | docker exec -i uied-api npx prisma db execute --stdin
```

如果报 `duplicate column name` 说明字段已存在，可以忽略。

### 步骤 5：重新生成 Prisma Client

```bash
docker exec -i uied-api npx prisma generate
docker restart uied-api
```

## 常用命令参考

| 命令 | 作用 |
|------|------|
| `npx prisma migrate deploy` | 应用所有待执行的迁移（生产环境用） |
| `npx prisma migrate resolve --applied "xxx"` | 标记某个迁移为已应用 |
| `npx prisma generate` | 重新生成 Prisma Client |
| `npx prisma db execute --stdin` | 执行原始 SQL |
| `npx prisma studio` | 打开数据库可视化界面 |

## 注意事项

1. **一条一条执行命令**：不要一次性粘贴多条命令，否则只有第一条会执行
2. **基线化不会执行 SQL**：`migrate resolve --applied` 只是在迁移记录表里标记，不会实际修改数据库结构
3. **容器隔离**：`docker exec -i uied-api` 只在指定容器内执行，不影响其他网站
4. **备份数据库**：重要操作前建议备份 `prisma/dev.db` 文件
