## 🔐 授权方案：简单实用

### 方案 A：最简单（推荐个人开发者）

**只验证授权码，不加密代码**

#### 工作流程
1. 用户购买后获得授权码
2. 安装时输入授权码
3. 后端验证授权码（调用你的授权服务器）
4. 验证通过后解锁 Pro 功能

#### 优点
- ✅ 实现简单（1-2 天）
- ✅ 不需要代码加密
- ✅ 用户体验好
- ✅ 易于维护

#### 缺点
- ❌ 用户可以看到源码
- ❌ 容易被破解

#### 适用场景
- 个人开发者
- 快速验证市场
- 前期用户量小

---

### 方案 B：中等复杂度

**授权码 + 域名绑定**

#### 工作流程
1. 用户购买后获得授权码
2. 安装时输入授权码和域名
3. 授权码绑定域名
4. 每次启动验证域名是否匹配

#### 优点
- ✅ 防止一码多用
- ✅ 实现相对简单（3-5 天）
- ✅ 用户体验可接受

#### 缺点
- ❌ 用户更换域名需要重新授权
- ❌ 仍然可以看到源码

#### 适用场景
- 有一定用户量后
- 防止恶意传播

---

### 方案 C：复杂但安全

**授权码 + 域名绑定 + 代码混淆**

#### 工作流程
1. Pro 版代码使用 webpack/vite 混淆
2. 关键功能代码混淆
3. 授权验证逻辑混淆
4. 定期在线验证

#### 优点
- ✅ 较难破解
- ✅ 保护核心代码

#### 缺点
- ❌ 实现复杂（1-2 周）
- ❌ 可能影响性能
- ❌ 调试困难

#### 适用场景
- 用户量大后
- 有盗版问题时

## 🛠️ 授权系统实现

### 最简单的授权验证（推荐）

#### 1. 授权服务器（你的服务器）

```javascript
// 授权验证 API
// https://license.fsuied.com/api/verify

app.post('/api/verify', async (req, res) => {
  const { licenseKey, domain } = req.body;
  
  // 查询数据库
  const license = await db.license.findOne({
    where: { key: licenseKey }
  });
  
  if (!license) {
    return res.json({ valid: false, message: '授权码无效' });
  }
  
  if (license.domain && license.domain !== domain) {
    return res.json({ valid: false, message: '域名不匹配' });
  }
  
  if (license.expiresAt < new Date()) {
    return res.json({ valid: false, message: '授权已过期' });
  }
  
  return res.json({ 
    valid: true, 
    type: license.type, // personal, business, enterprise
    features: license.features // 可用功能列表
  });
});
```

---

#### 2. Pro 版后端验证

```javascript
// backend/src/middleware/licenseCheck.js

const axios = require('axios');

const LICENSE_SERVER = 'https://license.fsuied.com/api/verify';

async function checkLicense(req, res, next) {
  try {
    // 从配置文件读取授权码
    const licenseKey = process.env.LICENSE_KEY;
    const domain = req.get('host');
    
    // 验证授权（每天验证一次，缓存结果）
    const cacheKey = `license_${licenseKey}`;
    let result = cache.get(cacheKey);
    
    if (!result) {
      const response = await axios.post(LICENSE_SERVER, {
        licenseKey,
        domain
      });
      
      result = response.data;
      
      if (result.valid) {
        // 缓存 24 小时
        cache.set(cacheKey, result, 86400);
      }
    }
    
    if (!result.valid) {
      return res.status(403).json({
        success: false,
        message: '授权验证失败: ' + result.message
      });
    }
    
    // 将授权信息附加到请求
    req.license = result;
    next();
  } catch (error) {
    console.error('授权验证错误:', error);
    // 网络错误时允许继续（避免影响用户使用）
    next();
  }
}

module.exports = checkLicense;
```

#### 4. 前端功能控制

```typescript
// frontend/src/hooks/useLicense.ts

import { useEffect, useState } from 'react';
import api from '../services/api';

interface License {
  valid: boolean;
  type: 'free' | 'personal' | 'business' | 'enterprise';
  features: string[];
}

export const useLicense = () => {
  const [license, setLicense] = useState<License>({
    valid: false,
    type: 'free',
    features: []
  });
  
  useEffect(() => {
    // 获取授权信息
    api.get('/license/info').then(res => {
      setLicense(res.data);
    });
  }, []);
  
  const hasFeature = (feature: string) => {
    return license.features.includes(feature);
  };
  
  return { license, hasFeature };
};
```

```tsx
// 使用示例
import { useLicense } from '../hooks/useLicense';

const Dashboard = () => {
  const { hasFeature } = useLicense();
  
  return (
    <div>
      {hasFeature('ai_search') && (
        <AISearchPanel />
      )}
      
      {hasFeature('statistics') && (
        <StatisticsPanel />
      )}
      
      {!hasFeature('statistics') && (
        <UpgradePrompt feature="数据统计" />
      )}
    </div>
  );
};
```

## 💡 关键建议

### 1. 先做最简单的授权

**不要一开始就做复杂的授权系统！**

- ✅ 只验证授权码
- ✅ 不加密代码
- ✅ 快速上线
- ✅ 验证市场

等有了收入和用户后，再考虑：
- 域名绑定
- 代码混淆
- 在线验证

---

### 2. Pro 版只提供构建文件

**不要开源 Pro 版！**

```
开源版：完整源码（GitHub）
Pro 版：构建文件 + 后端源码（付费下载）
企业版：完整源码（高价 + 源码授权）
```

**原因**：
- 前端构建文件已经足够难以修改
- 后端源码开放方便用户配置
- 平衡了保护和易用性

---

### 3. 定价要合理

**个人开发者建议定价**：

- **个人版**：¥199/年 或 ¥699/永久
- **商业版**：¥699/年 或 ¥1999/永久
- **企业版**：¥1999/年 或 ¥6999/永久（含源码）

**为什么比原计划低？**
- 你是个人开发者，品牌影响力小
- 需要快速获得第一批用户
- 价格低更容易成交
- 等有了口碑再涨价

---

### 4. 不要追求完美

**MVP 原则**：
- 只做核心功能
- 快速上线
- 收集反馈
- 迭代优化

**不要做**：
- ❌ 复杂的授权系统
- ❌ 代码加密
- ❌ 主题市场
- ❌ 插件市场
- ❌ 过多的功能
